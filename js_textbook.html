1. What is JavaScript?

JavaScript is a high-level, interpreted, and dynamically typed programming language. Originally created in 1995 by Brendan Eich to add basic interactivity to web pages, it has evolved into a powerful language used on both the client side (browsers) and the server side (Node.js).

Unlike languages like C++ or Java which require you to compile your code before running it, JavaScript is interpreted. This means the browser's JavaScript Engine reads and executes the code line-by-line.

Why Learn JavaScript?

  • Ubiquity: It is the only programming language native to the web browser.
  • Versatility: You can build web apps, mobile apps, desktop apps, and servers with it.
  • Community: It has the largest ecosystem of libraries and frameworks (like React, Angular, Vue).

3. Comments in JavaScript

When writing code, you often want to leave notes for yourself or other developers explaining what a piece of code does. These notes are called Comments.

Comments are completely ignored by the JavaScript engine when the code runs. They exist purely for human readability.

Two Types of Comments

  • Single-line Comments (//): Anything written after two forward slashes on that specific line is ignored.
  • Multi-line Comments (/* ... */): Anything enclosed between these symbols is ignored, allowing you to write paragraph-long explanations.

4. Values and Data Types

Every piece of information in JavaScript is a Value. To make sense of different types of information, JavaScript categorizes values into Data Types.

There are two main categories of data types in JavaScript: Primitives and Objects. For now, we will focus on the fundamental Primitives:

  • String: Used for text. Always enclosed in quotes.
  • Number: Used for decimals and integers. No quotes.
  • Boolean: A logical type that can only be true or false.

By using the typeof operator, we can ask JavaScript to tell us the data type of any given value.

5. Introduction to Variables

Imagine a variable as a labeled box where you can store a value. Once you store a value in that box, you can reuse it throughout your program by simply referring to the label (the variable name).

In modern JavaScript, we create variables using the let keyword. When you declare a variable with let, you are telling the computer's memory to reserve a spot for your data.

Rules for Naming Variables:

  • Names can contain letters, numbers, underscores, and dollar signs.
  • Names cannot start with a number.
  • Names are case-sensitive (age is different from Age).
  • Use camelCase convention (e.g., firstName, totalScore).

6. Updating Variables (let)

The keyword let stands for a variable whose value is allowed to change (mutate) over time. This is incredibly useful for data that constantly updates, like a user's score in a game, or their age.

When updating a variable, you do not use the let keyword again. You only use let when creating the variable for the very first time. To update it, you simply write the variable name followed by the equals sign and the new value.

Behind the scenes, JavaScript finds the 'box' in memory labeled with your variable name, throws out the old value, and puts the new value inside.

7. Constant Variables (const)

While let is great for changing data, sometimes we have data that should never change. For example, a person's birth year, or the mathematical value of Pi.

In 2015, JavaScript introduced the const keyword. When you declare a variable with const, you lock its value. Any attempt to update or reassign a const variable will cause your program to crash with an Error.

Best Practice:

Always use const by default! Only use let if you are absolutely sure that the value will need to change later in the program. This makes your code safer and prevents accidental bugs.

8. The Old Way: var

Before 2015, JavaScript only had one way to declare variables: the var keyword. You will still see var in older codebases and legacy tutorials.

Why did we move away from var? Because it has bizarre scoping rules (which we will cover later in the 'Scope' chapter) and allows you to accidentally redeclare the exact same variable twice without throwing an error, which causes massive bugs.

Modern Rule:

Avoid using var completely in modern JavaScript. Stick exclusively to let and const.

9. Undefined vs Null

In JavaScript, there are two special primitives that represent 'nothingness': undefined and null.

Undefined

When you declare a variable but do not assign a value to it, JavaScript automatically assigns it the value of undefined. It means 'this variable exists, but it has no value yet'.

Null

null is used when you, the developer, intentionally want to say 'this variable holds absolutely nothing'. It is an intentional absence of value.

Think of it this way: undefined is an empty box that you forgot to pack. null is an empty box that you deliberately left empty.

11. String Concatenation

Strings are text values. When you use the addition operator (+) on strings, JavaScript does not perform mathematical addition. Instead, it performs Concatenation, which means joining the strings end-to-end.

For example, 'Hello' + 'World' becomes 'HelloWorld'.

The Quirk of JavaScript Coercion:

If you try to add a String and a Number together (e.g., 'Score: ' + 10), JavaScript will secretly convert the Number into a String behind the scenes and concatenate them. This is known as Implicit Coercion.

14. Equality: Loose (==) vs Strict (===)

Checking if two values are equal is done using equality operators, but JavaScript has two different kinds: Loose Equality and Strict Equality.

Loose Equality (==)

Checks if the values are equal, but ignores the data type. If the types are different, JavaScript attempts to convert them (coercion) before comparing. 5 == '5' is true.

Strict Equality (===)

Checks if BOTH the value and the data type are identical. No conversion happens. 5 === '5' is false because one is a Number and the other is a String.

Golden Rule: Always use === (Strict) in modern JavaScript to avoid coercion bugs!

programenote.dev | Page 27 | Theory

Live Output:

Terminal / Console
> Loose check (5 == '5'): true > Strict check (5 === '5'): false > Strict check (5 === 5): true

Code Implementation:

let num = 5;       // Number
let str = '5';     // String

// Loose equality (Coercion happens)
console.log("Loose check (5 == '5'):", num == str);

// Strict equality (No coercion - Safer!)
console.log("Strict check (5 === '5'):", num === str);

// Strict equality with matching types
console.log("Strict check (5 === 5):", num === 5);

15. Logical Operators (AND, OR, NOT)

Logical Operators allow you to combine multiple boolean conditions together.

  • AND (&&): Returns true ONLY if all conditions are true. If even one is false, the whole expression becomes false.
  • OR (||): Returns true if at least one condition is true. It only returns false if all conditions are false.
  • NOT (!): Reverses the boolean value. true becomes false, and vice versa.

These are crucial when making complex decisions, like verifying if a user is both an Admin AND has an Active account.

Live Output:

let hasLicense = true;
let hasGoodVision = false;

// AND: Both must be true
let canDrive = hasLicense && hasGoodVision;
console.log('Can drive?', canDrive);

// OR: One must be true
let isStudent = true;
let isSenior = false;
let needsDiscountTicket = isStudent || isSenior;
console.log('Needs ticket?', needsDiscountTicket);

// NOT: Inverts the value
console.log('Inverted true is:', !true);

16. Control Flow: The if Statement

By default, code executes line-by-line from top to bottom. Control Flow allows us to change this path based on conditions. The most fundamental tool for this is the if statement.

The if statement evaluates a condition inside parentheses (). If that condition results in true, the code inside the curly braces {} (the block) will be executed. If it evaluates to false, the block is completely skipped.

This allows your program to be dynamic and react differently to different data (like showing a 'Welcome' message only if the user is logged in).

Code Implementation:

// The code inside the { } only runs because 20 >= 18 is true.
if (userAge >= 18) {
  console.log('You are an adult.');
}

let batteryLevel = 10;

// This block will be skipped because 10 < 5 is false.
if (batteryLevel < 5) {
  console.log('Battery critical! Please charge.');
}

17. The if...else Statement

While the if statement handles what to do when a condition is true, the else statement acts as the fallback. It handles what to do when the condition is false.

An else block cannot exist on its own; it must immediately follow an if block. This structure guarantees that exactly one of the two blocks will execute, making it a perfect tool for binary decisions (e.g., Login Success vs Login Failed).

  // Runs if the condition is true

} else {
  // Runs if the condition is false
  console.log('Access Denied. Please check your password.');
}

18. Multiple Conditions: else if

Sometimes a decision isn't just binary (True/False). You might have multiple distinct scenarios. This is where else if comes in.

You can chain as many else if blocks as you want between the initial if and the final fallback else. JavaScript will evaluate them from top to bottom. As soon as it finds a true condition, it executes that block and immediately exits the entire chain, skipping the rest.

This is extremely useful for grading systems, categorizing data, or handling multiple specific error codes.

programenote.dev | Page 35 | Theory

Live Output:

Terminal / Console
> Letter Grade: B

Code Implementation:

if (testScore >= 90) {
  console.log('Letter Grade: A');
} else if (testScore >= 80) {
  // This block runs! 85 is >= 80.
  console.log('Letter Grade: B');
} else if (testScore >= 70) {
  // This is skipped because a match was already found above.
  console.log('Letter Grade: C');
} else {
  console.log('Letter Grade: F');
}

19. Truthy and Falsy Values

In JavaScript, if conditions don't strictly require a boolean true or false. You can put any data type inside an if statement, and JavaScript will automatically coerce it into a boolean.

Falsy Values:

There are exactly 6 values that evaluate to false: 0, "" (empty string), null, undefined, NaN (Not a Number), and of course, false.

Truthy Values:

Literally everything else evaluates to true. This includes numbers like 1 or -5, any non-empty string like 'hello', and even empty arrays [] or objects {}.

Code Implementation:

  console.log('This string is Truthy!');
}

// 0 is Falsy, so the if block is skipped.
if (itemsInCart) {
  console.log('You have items to checkout.');
} else {
  console.log('0 is Falsy, so the else block runs.');
}

20. The Switch Statement

When you have a long chain of else if statements testing the same variable against different strict values, it can look messy. The switch statement provides a cleaner syntax for this.

The switch takes a single value and evaluates it against multiple case blocks using strict equality (===). When a match is found, it executes the code.

The Break Keyword:

Crucially, you must use the break keyword at the end of each case. If you forget break, JavaScript will "fall through" and execute all the code in the subsequent cases as well, regardless of whether they match!

programenote.dev | Page 39 | Theory

Live Output:

Terminal / Console
> The traffic light is Yellow: Slow down!

Code Implementation:

let trafficLight = 'Yellow';

switch (trafficLight) {
  case 'Red':
    console.log('Stop!');
    break;
  case 'Yellow':
    console.log('The traffic light is Yellow: Slow down!');
    break; // Stops execution here
  case 'Green':
    console.log('Go!');
    break;
  default:
    // Runs if no cases match
    console.log('Invalid color.');
}

21. Loops: Introduction to Iteration

In programming, we often need to perform the exact same task multiple times. Instead of copy-pasting the same line of code over and over (which violates the DRY principle: Don't Repeat Yourself), we use Loops.

Loops allow us to execute a block of code repeatedly as long as a certain condition remains true. The moment the condition becomes false, the loop stops, and the program continues.

The Danger of Infinite Loops

If you create a loop where the condition never becomes false, the loop will run forever. This is called an Infinite Loop, and it will crash the browser or the application by consuming all available memory and CPU power.

Live Output:

Terminal / Console
> Iteration 0 > Iteration 1 > Iteration 2 > Loop finished!

Code Implementation:

let count = 0;

// A basic loop structure (using while)

  console.log('Iteration', count);
  // Crucial step: we must change the variable 
  // so the condition eventually becomes false!
  count = count + 1;
}

console.log('Loop finished!');

22. The for Loop

The for loop is the most commonly used loop in JavaScript. It is perfect for situations where you know exactly how many times you want the code to repeat (for example, counting from 1 to 10).

The for loop consolidates three crucial pieces of looping logic into a single line:

  1. Initialization: Creating the counter variable (e.g., let i = 0;). This runs only once at the start.
  2. Condition: The rule that keeps the loop running (e.g., i < 5;). Checked before every iteration.
  3. Increment/Decrement: Updating the counter (e.g., i++). Runs at the end of every iteration.

Code Implementation:

// (Initialization; Condition; Increment)
for (let i = 1; i <= 3; i++) {
  // This code runs as long as i <= 3
  console.log(i);
}

// The loop finishes when i becomes 4 (4 <= 3 is false)
console.log('Blastoff!');

23. Break and Continue

Loops don't always have to run to their natural end. JavaScript provides two powerful keywords to manually control the flow inside a loop: break and continue.

Break

The break keyword immediately kills the loop entirely. It is often used when searching for a specific item. Once the item is found, there's no need to keep looping, so you break out to save processing power.

Continue

The continue keyword skips the current iteration and immediately jumps back to the top of the loop to evaluate the condition for the next cycle. It is used to skip over data you don't care about without killing the whole loop.

programenote.dev | Page 45 | Theory

Live Output:

Terminal / Console
> 1 > 2 > Found it! Stopping loop. > === Next Example === > 1 > 3 > 5

Code Implementation:

for (let i = 1; i <= 5; i++) {
  if (i === 3) {
    console.log('Found it! Stopping loop.');
    break; // Kills the loop completely
  }
  console.log(i);
}

console.log('=== Next Example ===');

for (let n = 1; n <= 5; n++) {
  if (n % 2 === 0) {
    // If the number is even, skip to the next iteration
    continue; 
  }
  console.log(n); // Only prints odd numbers
}

24. Introduction to Functions

A Function is a reusable block of code designed to perform a specific task. Think of it as a mini-program within your main program.

Why use Functions?

If you have a block of logic that you need to use in 5 different places, you shouldn't copy-paste it 5 times. Instead, you wrap it inside a Function. Then, you simply "call" or "invoke" that function whenever you need it.

Anatomy of a Function:

  • Declaration: Use the function keyword, give it a name, and add () and {}.
  • Invocation: To actually run the code inside, you must call the function by writing its name followed by parentheses: myFunction().

25. Function Parameters and Arguments

Functions become truly powerful when they can accept data from the outside, process it, and act dynamically based on that data.

Parameters (The placeholders)

When you declare a function, you can define variables inside the parentheses. These are called Parameters. They act as placeholders for the data the function expects to receive.

Arguments (The actual data)

When you invoke the function, the actual values you pass into the parentheses are called Arguments. JavaScript maps the arguments to the parameters in the exact order they are passed.

26. Return Values

So far, our functions have only printed things to the console. But in real-world applications, functions usually calculate a result and send it back to the main program to be used later. We do this using the return keyword.

When JavaScript encounters a return statement, two things happen immediately:

  1. The function completely stops executing (any code below the return is ignored).
  2. The value specified is "spit out" (returned) to wherever the function was called.

You can then store this returned value in a variable to use it elsewhere.

Live Output:

Terminal / Console
> Result of 5 + 10 is: 15 > Result of 100 + 200 is: 300

Code Implementation:

function addNumbers(a, b) {
  let sum = a + b;
  // Send the result back to the caller
  return sum;
  
  // This will never run!
  // console.log('I am invisible'); 
}

// Store the returned value in a variable
let finalResult = addNumbers(5, 10);
console.log('Result of 5 + 10 is:', finalResult);

let anotherResult = addNumbers(100, 200);
console.log('Result of 100 + 200 is:', anotherResult);

27. Variable Scope: Global vs Local

Scope defines the accessibility (visibility) of variables. Not all variables are accessible from everywhere in your code.

Global Scope

A variable declared outside of any function has Global Scope. It can be accessed and modified from anywhere in your JavaScript file. This can be dangerous if overused.

Local (Function) Scope

Variables declared inside a function are Local to that function. They are completely hidden from the outside world. They are created when the function starts and destroyed when the function ends. This provides security and memory efficiency.

programenote.dev | Page 53 | Theory

Live Output:

Terminal / Console
> Inside function: Global Data > Inside function: Secret Local Data > Outside function: Global Data > Error: secretData is not defined

Code Implementation:

42. Asynchronous JavaScript Introduction

JavaScript is a Single-Threaded language, meaning it can only execute one line of code at a time on a single main thread. If a piece of code takes 5 seconds to run (like downloading a large image), the entire webpage would freeze for 5 seconds!

The Solution: Asynchronous Programming

To prevent the browser from freezing, JavaScript offloads heavy tasks (like timers or fetching data from a server) to the browser's Web APIs. The browser handles the heavy lifting in the background, and when it finishes, it alerts JavaScript to execute a callback function.

This allows JavaScript to continue running other code smoothly while waiting for background tasks to finish.

44. Introduction to Promises

A Promise is an object representing the eventual completion (or failure) of an asynchronous operation. Think of it like a restaurant buzzer: you place your order, and they hand you a buzzer. The buzzer is a "promise" that you will eventually get your food.

The 3 States of a Promise:

  1. Pending: The initial state. The background task is still running. (You are waiting for the food).
  2. Fulfilled (Resolved): The task completed successfully! (The buzzer rings, your food is ready).
  3. Rejected: The task failed due to an error. (The kitchen ran out of ingredients).

46. Async and Await (Modern JS)

While .then() and .catch() solved Callback Hell, chaining them could still look messy. In 2017, JavaScript introduced Async / Await, which is syntactic sugar over Promises.

It allows us to write asynchronous code that looks and behaves like synchronous, line-by-line code!

How it works:

  • Put the async keyword in front of a function to declare it as asynchronous.
  • Inside that function, use the await keyword in front of any Promise.
  • The function will literally pause execution at the await line until the Promise resolves, and then store the result in a variable.
